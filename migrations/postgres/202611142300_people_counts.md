# Owner-scoped People counts

The former overview ran repeated RLS scans and invoked current-face ownership
lookups for each face. The aggregate functions avoid repeating these lookups
for each overview row.

These two fixed aggregate functions return only counts for the authenticated
owner. They accept no username argument, expose no face embeddings, and enforce
current album ownership through joins. Shared viewers and administrators still
receive only their own counts. Existing row policies and correction writes remain
unchanged. Anonymous callers receive zero totals and no person rows. PUBLIC has
no execution grant; the existing app role is the only explicit grantee.

Apply this additive migration before deploying the app change. The previous app
remains compatible. Rollback the application first; unused functions can remain.
Validate with owner/cross-owner/anonymous/moved-album/ignored-face tests and
compare count results and query times against the former SQL on the same snapshot.

## Validation

Compare old and new totals in one repeatable-read snapshot, including ordered
pages. Record database timings separately from API/browser measurements in private
release evidence.

Regression coverage includes pagination, corrections and undo, ignored suggested
faces, no identity, shared viewers, administrator identity isolation, cross-owner
person IDs, album transfer and photo transfer. The person detail now excludes
ignored suggestions from its review count, consistently with the overview.
The face-image batch transport and upload pipeline are unchanged.
